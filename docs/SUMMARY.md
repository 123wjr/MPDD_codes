## 关键结论

### 1) HelloWorldLTY —— 重点问题对象
- **Track 2 Young 存在明确不正当手段**（取证见 `audit_HelloWorldLTY.md`）：
  - **往届标签泄漏**：22 个测试 ID 中有 18 个，其真实 `binary/tri/PHQ-9` 标签
    直接从 **MPDD-2025** 的 `personalized_train.json` 读入，并用于对候选集成"打分排序"。
    `LEAK = [1,7,13,28,33,34,40,42,44,58,74,83,85,89,90,93,105,110]`。
  - **排行榜试探 (leaderboard probing)**：剩余 4 个未泄漏 ID `{5,15,22,47}` 通过反复提交
    观察分数变化反推真值（脚本 docstring 自述 "ens95/ens102 在 CodaBench 上测得…"）。
  - **手工调参**：最终对 id47 的 PHQ 做一维 maximin 扫描硬调。
  - 选手 README 自己承认："label leak"、"leaderboard-derived decisions"、Stage B
    "不是一个能泛化的模型，只是用泄漏标签编辑了少数测试单元格"。
  - **从头、无泄漏复现只能到 ~0.566**，与自称 ~0.62 差约 0.05+。
- **Track 1 Elder**：方法透明但"最佳提交"是把冻结的参考 zip 重新按 PHQ 阈值(2.5/5.0)
  生成（`reproduce_best.py` 仅需标准库、无需训练）。真正 Stage A 从头训练会因
  库/硬件版本漂移使 PHQ 漂移 ±0.2，从而翻转边界样本(id51)，**从头约 0.56–0.57，
  低于自称 0.5881**。无标签泄漏，但严格意义上不满足"从头复现得到同分"。

### 2) JerryYe748 —— 无法从头复现
- 仓库**只有消费 .npy 的训练/推理代码，没有任何特征抽取代码**；WavLM、Whisper、
  LCO、OpenFace3、YOLOv11 骨架等特征全部以预打包 .npy 随 Release 提供，权重(.pth/.cbm)
  也随包。**脱离选手随包文件无法复现**。
- 使用**非官方**更强特征流水线（官方是 OpenFace2，其用 OpenFace3；骨架用 YOLOv11；
  音频用 WavLM/Whisper-large-v3/LCO-Omni-7B）——属规则问题，模型架构强依赖这些特征。
- 训练 epoch 被钉死（binary/phq=43, ternary=45）且 `preserve_shuffle_sequence` 注入随机，
  结果绑定到特定训练轨迹，**重训不易复现同分**。
- **未发现**测试集标签泄漏或 per-id 硬编码（辅助 CatBoost 仅在"二/三分类不一致样本"
  上做全局阈值决策，非按 ID 覆盖）。

### 3) buptlyx —— 干净、可从头复现
- 含完整 `feature_extract/`（音频 mfcc/opensmile/wav2vec、视频 densenet/resnet/openface），
  可从原始数据重抽特征；训练/验证/测试严格分离，验证集仅从官方 train 内按 ID 分层切分，
  **测试集只在最后评测一次**；best ckpt 仅按验证集指标选；仓库未提交权重（.gitignore 排除 .pth）。
- **唯一注意**：数据发布中 Young 测试集 `Video/densenet|resnet|openface` 为 **0 字节空文件**，
  测试时视频分支被零填充 → **Track2 A-V-P / A-V-G-P 的测试分数不能反映视频贡献**，
  解释其成绩时须注明（这是数据集问题，非选手作弊，选手已在 README 透明说明）。
